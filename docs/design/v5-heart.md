# V5 階段 4:心

2026-11-17 開始。這份文件是階段 4 的現況、結論、要 owner 決定的事和工作順序。上層設計在 [v5-architecture.md](v5-architecture.md) §8,資料表在 [v5-data.md](v5-data.md),大腦在 [v5-brain.md](v5-brain.md)。

現況是三份唯讀盤點的結果(從 `packages/core/src/modules.ts` 往下追,只讀程式,沒有執行,也沒有讀線上設定和資料)。

## 1. 現況

### 1.1 三個模組都還在跑

| 模組 | 做什麼 | 模型呼叫 |
|---|---|---|
| `heart/social` | `relationships` 表(羈絆、信任、熟悉、標籤、稱呼);關鍵字規則和一次「社交評估」改數值;每筆變動寫 `relationship_deltas` | 每個有新訊息的頻道安靜 90 秒就一次,沒有每小時上限;另有印象筆記,每人每 12 小時最多一次 |
| `heart/self` | 她自己的 14 種情緒、驅力、對每個人的「在意」(程式裡叫 `romance`)和四種對人的情緒;全部在一個 `self:state` JSON 裡,每 60 秒整份重寫 | 無 |
| `heart/mind` | Appraise(對話安靜 120 秒後另一次呼叫替她選情緒、改對人的感覺)、Plan、目標、生活紀錄、提醒 | Appraise 每小時最多 6 次;Plan 每小時最多 12 次 |

### 1.2 問題

1. **說話的她碰不到自己的情緒**。她寫的 `<emo:名稱 強度>` 只送去語音和模型動作,強度在 `StepText` 就丟掉,不會改情緒。情緒由規則表和 120 秒後的 Appraise 決定。
2. **一段對話有兩次評估呼叫**。social 的評估和 mind 的 Appraise 都在跑,各改各的數值。
3. **數值由固定加減分的規則表推動**:問候 +0.5、道謝 +1、稱讚 +1.5、侮辱 −3 等等,每天上限 8。和 §8.3「她提出,程式限速」相反。
4. **Appraise 的改動記錯原因、繞過上限**:記成 `reflect: 剛剛的互動`,不經 social 的每日上限,還會吃掉每晚反思當天的額度。
5. **「在意」幾乎動不了**。切換後每個人從 0 開始,只有每晚反思能加(每人每天最多 0.03),到「在意」的門檻 0.3 要連續十個晚上以上。在那之前,想念某人而私訊、在意的人上線時的反應、暗戀對象這些功能都不會發生。
6. **新大腦看到的心很少**。正式的人物區塊(`PersonProfiles`)沒有對人的情緒、沒有在意的程度;而且區塊 4 是快取的,羈絆和感覺變了要等名單變動或對話壓縮才看得到。
7. **情緒的輸出大多沒有接到行為**。「想主動」「想做什麼」只餵給 Plan,而 Plan 在階段 3 之後什麼都啟動不了(它只改目標和當日計畫,每小時最多 12 次呼叫)。真正接到行為的只有:看一眼的額度、語音和模型的情緒標籤、想念到一定程度的私訊機會。
8. **羈絆和信任不會掉**。熟悉只在對方下一次說話時才補算衰減。「久沒來會掉,但只掉到已達成的分級」沒有程式。
9. **75 以上分不出來**。會員頁、會員卡、OG 圖都用六段文字,75 就滿了;`/me profile` 對「知心」以上的 12 個分級和陌生人回同一句「你誰啊?我們又不熟。」。
10. **分級名稱抄了四份**(契約的 enum、面板的色調表、Discord 的台詞表、V4 的對照表),會員的六段文字抄了兩份。
11. **三套「在意」的門檻**:world 用羈絆 30,self 和 social 用 40,mind 和主動用在意 0.3。
12. **面板有兩個人物清單**(角色 → 人、內心 → 感情),各打各的 API。面板沒有任何環狀的元件。
13. **唱歌依賴 mind**:歌準備好時去叫 Plan,而 Plan 不能開始唱;只有提醒次數用完才會自己開始。
14. social 的印象筆記花了模型呼叫,但沒有任何提示詞讀它。
15. Appraise 的片段在額度用完或預算不足時直接丟掉,不是延後。
16. 她寫 `@名字` 只能 tag 最近在那個頻道說過話的人(名字比對的問題已另外修,PR 62)。

### 1.3 沒問題、要留的

- 情緒引擎本身(增益、衰減、習慣化、互相抑制、每 10 分鐘的預算、傲嬌的遮掩)。
- 每一筆變動都有紀錄的做法。
- 對外只給文字、不給數字的原則(`contracts/api/src/member.ts` 開頭那句)。
- 會員頁的回應會照 schema 驗證並去掉多餘欄位。

## 2. 設計

### 2.1 `feel`:她自己說

她每次說話的那次模型呼叫,在回覆的最後多寫一段不顯示的 `<feel>`:

```
<feel>
我: 開心 中
小明: 羈絆 + 「他記得我上次說想吃的東西」
</feel>
```

- 第一行是她此刻的情緒和強度(弱、中、強),取代 Appraise 的那次呼叫。
- 後面每行是對在場某個人的小幅提議:哪個值、往上或往下、一句引用當原因。一回合最多兩個人。
- 用標籤而不是工具:工具呼叫會多一輪模型呼叫;標籤寫在最後,文字已經送出、語音已經在唸,不增加延遲。解析器把整段吃掉,寫錯格式也不會顯示出來。
- 她沒有數字可以寫。提議只有方向,幅度由程式決定。
- 沒寫 `<feel>` 的回合就沒有變動,不補一次呼叫。她沒說話的場合(她在場聽、唱歌、遊戲)由每晚反思處理。
- 語音也用同一段,但規則裡寫明可以省略。
- 階段 3 的評測加兩項:`<feel>` 有沒有漏到畫面或語音;提議的方向和對話合不合。

### 2.2 人物模型

一張 `heart_person` 表,一個人一列:羈絆(−100..1000)、信任、熟悉、好感、敬意、自在、心結、想念、默契,加上文字欄位(立場、印象、還沒聊完的事、共同的梗、她不喜歡對方的地方)、對外的一句話、`tier_floor`(已達成的最高分級)、分級的錨點記憶。

每一筆變動是一個 `heart.changed` 事件:`{person, field, delta, reason_quote, cause}`。`cause` 是 `feel`、`reflect`、`evidence`(唱歌、遊戲、禮物這類)、`decay`、`admin`。不另外開 delta 表;人物頁的變動紀錄從事件讀。

現有的 `relationships`、`relationship_deltas`、`self:feeling:*` 和 `self:state` 裡的 `hearts`,用一個搬移程式轉進新表(切換後才幾天的資料,但已經是她和人的關係,不丟)。「在意」併進好感和羈絆,不再是一個獨立的數字(見 H5)。

`heart_self` 放她自己的情緒和驅力,只在有變動時寫,不再每 60 秒重寫。

### 2.3 規則

- **她提出,程式限速**。一個提議的幅度是固定的一小步;同一個值同一天第 n 次只算 0.5ⁿ;負面是正面的三倍;每個值有每日上限。
- **羈絆的每日上限隨分級變小**(H3),這就是「前快後慢、約六個月」。
- **高分級要錨點**(H4):羈絆到了門檻但沒有錨點,就停在門檻前一點。
- **衰減**:七天沒有任何互動後,羈絆每天掉一點,只掉到 `tier_floor` 的門檻;好感往羈絆決定的基準回落;想念在不見面時上升;心結會淡但不會自己歸零。每天算一次,不等對方下一句話。
- **所有互動都是證據**:語音同處的時間、聽她唱歌、一起玩、禮物、守約和毀約,都寫成 `evidence` 事件。它們不直接加分(禮物維持現有的一點點),而是每晚反思時她會看到「今天和這個人發生了什麼」。
- 固定加減分的關鍵字規則表刪掉。social 的評估呼叫、印象筆記、mind 的 Appraise 刪掉。
- 管理員手動調整留著,一樣記事件。

### 2.4 每晚反思:一個人一次

現在的反思是一次呼叫看所有事,最多改 5 個人。改成:當天有互動的每個人各一次呼叫(高思考),讀當天和這個人的事(對話片段的筆記、證據事件、白天她自己提的變動)和現有的文件,做三件事:改寫文字欄位;核對數值(可以把白天的提議修正回來,一樣受上限);夠格的時候指定一段記憶當分級的錨點。

一晚最多處理的人數有上限,先處理當天互動多的;在每晚的花費上限之內。整體的反思(心得、她自己的文件)照舊。

### 2.5 大腦怎麼看到

- 人物區塊加上:對這個人的八個值(用文字描述,不是數字)、心結和想念高的時候的提示。
- 會變的部分(好感、心結、想念)移到區塊 7 的 `<now>`,不受區塊 4 的快取影響;區塊 4 只留慢變的(分級、立場、印象)。
- 情緒變成參數:看一眼的額度(已有)、主動的意願(直接接到 `initiative` 的機會權重,不再經過 Plan)、反應表情的機率。回覆長短寫進 `<style_note>` 一句話,不用程式硬切。
- 一個「在意」的定義,world、self、主動都用它。

### 2.6 mind 留什麼

| 部分 | 處理 |
|---|---|
| Appraise | 刪,由 `feel` 取代 |
| Plan、每日 Plan、`desire`、`SelfStarts` | 刪。它們在階段 3 之後已經不影響行為 |
| 想法日誌 | 留著,改成記 `feel` 和反思;面板的「內心」頁照舊讀它 |
| 目標 | 留著(區塊 7 和反思在讀);觸發條件改成叫醒新的 runner,而不是 Plan |
| 生活紀錄、提醒 | 留著 |
| 唱歌對 mind 的依賴 | 改成歌準備好就送一個 impulse 給她,由她決定現在唱不唱 |

### 2.7 顯示

- **一個環**的元件放在面板和 `card-face` 都用得到的地方,畫法照 H1。Discord 用同一份 SVG 轉成 PNG(`og.ts` 已經有 resvg)。
- **管理面板**:兩個人物清單併成「角色 → 人」一頁。清單每列一個小環;點開是人物頁:大環和確切數值、八個細項的長條、變動紀錄(每筆有引用的原因)、她寫的文件、手動調整。「內心 → 感情」拿掉。
- **會員頁**:環加分級名稱加「離下一級」的文字,沒有數字;信任和熟悉維持文字分段;她對外的那句話照舊。
- **Discord `/me profile`**:同一張環的圖加分級名稱;每個分級一句她的話,不再掉到陌生人那句。
- 分級名稱和門檻只留 `packages/types` 那一份,其他地方從它產生。會員的文字分段改成涵蓋到 1000。
- 她能 tag 的人加上:語音頻道裡的人,和這一回合提示詞裡出現的人。

## 4. 工作順序

每一步結束時 typecheck 和碰到的套件的測試要過;整套測試在背景的檢查 worktree 跑。

1. **資料和規則**:`heart_person`、`heart_self`、`heart.changed`;限速、上限、衰減、分級和錨點的純函式;搬移程式。先不接任何東西。
2. **`feel`**:解析器吃掉 `<feel>`;規則文字;套用到情緒引擎和人物模型;評測兩項。
3. **讀的那一邊**:`PersonProfiles` 和區塊 7 改讀新表;一個「在意」的定義;情緒接到主動和反應。
4. **每晚反思一個人一次**;證據事件(語音、唱歌、遊戲、禮物、約定)。
5. **刪舊的**:social 的規則表和評估、mind 的 Appraise、Plan、`SelfStarts`、`desire`;唱歌改用 impulse;`relationships` 兩張表在搬移後不再寫。
6. **API 和契約**:人物的 admin 路由合併;會員路由加環要的欄位(分級、分級內進度、圈的顏色,沒有數字)。
7. **顯示**:環的元件;面板人物頁;會員頁;`/me profile`。
8. **從啟動路徑稽核**一次(沒看過我結論的 worker),再跑真模型評測和舊的比。

1 到 5 是一條線,前後相依;6 和 7 在 1 的表定下來之後可以同時做。

## 5. 不在這個階段

- `admin` / `web` 拆開和 `packages/ui`(階段 6);這個階段的環先放在兩邊都引用得到的現有套件。
- 每個 Space 各自的設定(階段 6)。
