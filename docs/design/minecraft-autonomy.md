# Miyoria Minecraft 自主遊玩系統設計

2026-11-12 起草(owner)。2026-11-14 收進 repo;V5 怎麼接它見 [v5-architecture.md](v5-architecture.md) 和 [v5-play.md](v5-play.md)。

## 目標與設計原則

結論：把現在「每 20 秒問 LLM 下一個目標」的導演，換成「她自己有一份長期議程，議程永遠不空，執行層永遠有事做」的三層系統。通關只是議程裡的一種長期志向，跟蓋房子、陪人玩、探索、收集並列。

要達成的五件事和驗收方式：

| 需求 | 做到的意思 | 怎麼量 |
| --- | --- | --- |
| 真正自主 | 沒人講話時，她從自己的志向、心情、世界狀態推出下一件事，而且說得出為什麼 | 一場 2 小時裡，她自己開的目標占 80% 以上，且每個目標都連到一個志向 |
| 不停下來、不卡住 | 身體閒置不超過 5 秒；同一件事沒進展超過預算就自動換方法或換目標 | 閒置秒數占比 < 5%；「連續沒進展」最長 < 4 次（11-08 那場是 25 次） |
| 不只通關 | 志向有很多種，通關是可選的一條 | 一場裡至少碰到 3 種不同志向 |
| 多人互動 / 獨自玩 | 有人在時，聊天、請求、一起做事能插隊；沒人時自己玩 | 玩家請求 30 秒內有回應；請求有接、拒或協商三種結果 |
| 蓋建築 | 能選地、備料、照藍圖蓋，也能用 LLM 生成的小藍圖 | 從空背包蓋出一間 5x5 小屋，人不介入 |

設計原則：

- **快慢分離**：逐幀的事（保命、脫困、撿東西）不經過 LLM；LLM 只管「要做什麼」和「怎麼講」。
- **議程永遠不空**：LLM 慢或失敗時，執行層從議程裡拿下一個能做的；什麼都不能做時，有「閒置行為」墊底（整理背包、在附近採集、看風景講話）。
- **進展才算數**：沿用現有的 `GameTaskOutcome`，沒進展的「完成」等於失敗。
- **沿用現有骨架**：Fabric 模組 + Baritone + adapter 的任務契約不換，新東西加在導演和 adapter 之間。

## 參考專案

沒有一個專案同時做到五件事；各拿一塊：AIRI 的分層、Voyager 的自動課程和技能庫、Mindcraft 的常駐模式和多人協作、Project Sid 的並行模組、Neuro SDK 的動作契約。

| 專案 | 做法 | 我們拿什麼 |
| --- | --- | --- |
| [AIRI Minecraft](https://mintlify.com/moeru-ai/airi/integrations/minecraft) | mineflayer bot；四層 Perception → Reflex → Conscious → Action；Reflex 管自動吃、閃躲、閒置時看四周；Conscious 是 LLM 管目標階層。目標主要來自聊天指令，文件沒寫自主選目標和防卡死 | 分層命名和「閒置也是反射」的想法；我們已經有反射層，缺的是目標階層 |
| [Voyager](https://arxiv.org/abs/2305.16291) | 自動課程（按「能探索到新東西」出題）、會長大的程式碼技能庫、用環境回饋和自我驗證反覆修正 | 自動課程的精神變成「志向 → 目標」的生成器；技能庫已有雛形（`skill-store.ts`），加上檢索 |
| [Mindcraft](https://cdn.jsdelivr.net/gh/mindcraft-bots/mindcraft@develop/README.md) | mineflayer；LLM 下高階指令，可選開 LLM 寫程式（`allow_insecure_coding`）；任務 JSON 有 `timeout`、`blocked_actions`；支援多個 bot 和人一起玩。常駐「模式」（自保、脫困、撒活、撿東西、閒置看人）和自我提示的長期目標是印象中的做法，這次 README 裡沒看到 | 「自我提示」：沒人講話時自己給自己下一個指令；不採用 LLM 寫任意程式（風險高、直播不穩） |
| [MineCollab](https://arxiv.org/abs/2504.17950v1) | Mindcraft 上的協作基準；要用語言交代詳細計畫時表現掉到 15% | 多人協作的對話要短，分工用結構化的「請求」而不是長計畫 |
| [Project Sid / PIANO](https://arxiv.org/abs/2411.00114) | 多個模組並行跑，由「認知控制器」統一輸出，讓講話和動作不打架；10 到 1000+ 個 agent | 講話和動作分兩條車道，由同一份「現在在做什麼」狀態對齊，避免嘴上說 A 手上做 B |
| [Neuro Game SDK](https://raw.githubusercontent.com/VedalAI/neuro-game-sdk/main/API/README.md) | 遊戲註冊動作（名稱 + schema），她只從裡面挑；失敗要附看得懂的說明。Neuro 本人怎麼玩 Minecraft 沒公開，網路文章（[例](https://thetoolstrunk.com/how-does-neuro-sama-play-minecraft/)）都是推測 | 我們已經是這種架構；另外學「好笑的失敗也是節目」，卡住時講出來比安靜重試好 |

雷區：AIRI 和 Mindcraft 都是 mineflayer（一個無畫面的假玩家），我們是「真的開客戶端」，他們的容錯設計可以借，程式不能直接搬。

## 系統架構

新的核心是導演和 adapter 中間的「議程層」：它用規則快速挑下一個目標，LLM 在旁邊非同步地改議程，所以 LLM 慢、失敗或不說話都不會讓她停下來。

(原文件這裡有一張示意圖:四層 + 社交線 · 議程層是新的核心)

執行層做完或卡住就回報議程，議程立刻給下一個；LLM 只在旁邊改議程，不擋住身體。

### 四層加一條社交線

| 層 | 負責 | 速度 | 位置 | 狀態 |
| --- | --- | --- | --- | --- |
| L0 反射 | 保命、脫困、吃東西、撿東西，加上新的「閒置墊底」 | 每 tick | 模組 `Reflexes.java` | 已有，補 #5 的兩個修正 |
| L1 執行 | 一個目標變成一串步驟（`obtain`、`build`、`hunt`…），加上進展看門狗 | 秒 | adapter | 已有，補看門狗 |
| L2 議程 | 志向 → 專案 → 目標的樹；用分數挑下一個，永遠備好 3 個 | 亞秒，不叫 LLM | `packages/game/src/agenda.ts`（新） | 新 |
| L3 心智 | 提新專案、拆目標、反省、寫日記、決定要不要接玩家的請求 | 專案結束或每 5 分鐘 | 工作車道上的任務（V4 §4.3） | 取代現在每 20 秒的決定 |
| 社交線 | 玩家模型、請求佇列、聊天和語音評論 | 事件驅動 | `packages/game` + `social` | 新 |

### 目標系統：志向、專案、目標

- **志向**（長期，可以好幾場）：安家（有床、有家、有農場）、蓋東西、探索（新生態域、村莊、遺跡）、收集（所有花、唱片、寵物）、陪人玩、通關（可選）、節目效果（觀眾投票的事）。初始清單和權重寫在人設裡，她自己可以增減。
- **需求値**（類似模擬市民）：飢餓、安全、無聊、社交、創作、成就。每個需求沒被滿足時會慢慢升高，對應的志向就更想做。這是自主的來源：沒人講話也會「想」做事。
- **專案**（幾分鐘到一小時）：例如「在河邊蓋一間木屋」。由 LLM 用固定 schema 提出：`{aspiration, title, why, success, subgoals[], budget_min}`，`success` 必須是程式判斷得了的條件（背包、位置、建築驗證）。有點像 Voyager 的自動課程，但出題依據是志向和人設，不只是「探索新東西」。
- **目標**：現在的 `want` + 動作，交給 L1。
- **挑下一個**（無 LLM）：分數 = 需求値 × 可行度（規劃器說現在做得到嗎）× 新鮮度 − 最近失敗懲罰 + 觀眾 / 玩家加成。展開專案時先做前置（沒斧頭就先做斧頭），這部分用現有規劃器。
- **通關**是一個志向：它的專案是「做鐵套」、「進地獄」「拿 12 個終界之眼」…，每個都有自己的成功條件；裝了 AltoClef 時可以對整個志向開一個標明是 `beatgame` 的長任務，不假裝成個別里程碑。

### 不停、不卡：四層防線

1. **閒置偵測**：身體沒任務超過 3 秒，議程層直接拿備好的下一個目標；LLM 的決定在背景跑，回來後只改議程。議程沒有可做的就做墊底活動（附近採集、整理、看風景講話）。
2. **進展看門狗**（L1）：每個任務宣告它的進展訊號（位置變化、背包變化、計畫步驟、方塊放下數），超過訊號窗口（例如 45 秒）沒動就是卡住，不用等到預算用完。在同一個 3 格範圍內 60 秒而任務該移動，也算卡住。
3. **升級階梯**：同做法重試一次 → 換策略（`plan` / `altoclef` / 換地點 explore）→ 放棄這個目標、專案標成「卡在 X」並做兄弟目標 → 換志向。現有的做法暫停（`methods.ts`）就是第 2 階，接上去就好。
4. **死路記憶**：地點記憶記下「這裡是海」「這裡找過沒鐵」，下次 explore 往別的方向；11-08 在海上漂半小時的情況由這個擋。

卡住時也讓她講出來（「喔這個老是挖不到，先去蓋房子好了」），對直播來說是節目，不是安靜重試。

### 記憶

- **地點**：家、箱子內容、她自己放的工作台和熔爐（只回收自己的）、村莊、死亡點、別人的建築範圍。存在 store，以世界為單位，跨場次保留。
- **技能**：沿用 `skill-store.ts`，加上按情境檢索（沒石頭怎麼做石鎬）。不讓 LLM 寫可執行程式碼，技能是「動作序列 + 前置條件」。
- **日記**：每個專案結束寫一句話，接到她的主記憶，在 Discord 也能聊「昨天在 Minecraft 蓋了什麼」。

### 多人互動

- **場景偵測**：單人 / 和朋友 / 公開伺服器，決定講話頻率和規矩。
- **玩家模型**：每個名字一筆：關係（主人 / 朋友 / 陌生人）、信任度、一起做過的事。和 Discord 的社交記憶對到同一個人。
- **聊天分類**：閒聊 / 請求 / 指令。請求變成議程裡的「社交專案」，優先度看信任度；她可以接、拒或討價還價（「等我蓋完這面牆」）。主人的指令可以打斷。參考 MineCollab 的結論，協作用短的結構化請求，不講長計畫。
- **合作動作**：跟著、給東西（用 #5 的 `drop` 丟向對方）、幫忙採集、一起蓋同一份藍圖、保護。
- **規矩**：不拆不是自己放的方塊（別人建築範圍設成 Baritone 的不可破壞區）、不主動 PvP、聊天限速、過審核（沿用 `moderation`）。公開伺服器上 Baritone 可能算作弊，只進允許的伺服器。

### 蓋建築

- **藍圖來源**：(a) 手工 `.schem` 庫（幾種風格的屋子、農場、塔）；(b) 參數化模板（寬、深、高、材料、屋頂形狀）；(c) LLM 生成的小建築，用「一層一張字元圖 + 調色盤」的 JSON，尺寸限 9x9x7，程式驗證後轉成 schematic。
- **流程**：選地（平、不在別人範圍、靠近家）→ 算材料清單 → 每種材料變成 `obtain` 子目標（木材可以互換）→ 整地 → Baritone `build` → 掃描驗證差異並補完 → 記成地點（「家」）。
- **模組要補的請求**：`scan_area`（一個方塊內的方塊，選地和驗證用）、實體座標（打獵也要）、開箱子讀寫、`drop`。

## 實作路線

先讓她「不停」，再讓她「想做事」，最後才加社交和蓋房子；每階段以一場實機遊玩當驗收，沒過不進下一階。

1. **P0 整理與實機基準**：處理 #5 / #6（上一節）；模組加實體座標；用 11-08 的開局（晚上、海裡、8 血）實玩一場、量閹置比例和連續沒進展。關卡：有一份真實的基準數字。
2. **P1 不停不卡**：閒置偵測、進展看門狗、升級階梯、墊底活動、地點記憶（死路）。關卡：閒置 < 5%、連續沒進展 < 4。
3. **P2 議程層**：`agenda.ts`、需求値、志向清單寫進人設、LLM 提專案的 schema 和驗證、導演改成非同步。關卡：無人介入 2 小時，自己開的目標 ≥ 80%，碰到 ≥ 3 種志向。
4. **P3 蓋建築**：`scan_area`、參數化小屋模板、材料清單 → `obtain`、選地、驗證補完；然後才是 LLM 生成藍圖。關卡：從空背包蓋出 5x5 小屋。
5. **P4 多人**：玩家模型、聊天分類、請求佇列、合作動作、不拆別人的東西。關卡：和 Owen 在自架伺服器玩 1 小時，請求 30 秒內有回應、沒有拆到別人的方塊。
6. **P5 長期志向**：通關志向（用 #6 的配方）、收集、觀眾投票加成、日記接主記憶。

P1 和 P2 是最重要的兩階：做完就能解決「一直停下來」和「不知道要幹嘛」。

## 風險與待決問題

- **還沒實機驗證**：現在的自主能力只在測試裡跑過。P0 的基準可能讓優先順序改變。
- **LLM 的花費和延遲**：改成專案級的決定後呼叫次數應該變少，但反省和專案提案的 prompt 較長。
- **伺服器規則**：Baritone 在很多公開伺服器算作弊。先只做單人和自架伺服器。
- **藍圖品質**：LLM 生成的 3D 結構常常不對稱或會懸空，所以模板優先、LLM 的放後面。
- **待 Owen 決定**：
  - （已決定）#5 / #6 經 #29 整合進 main。
  - 她的志向清單和權重（她更喜歡蓋東西還是冒險？）。
  - 在多人伺服器誰算「主人」，可以打斷她。
  - AltoClef 是否要變成必裝（通關志向會更順）。
