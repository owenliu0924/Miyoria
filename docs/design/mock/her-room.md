# 她的房間(示意)

`her-room.html` 是一頁示意圖:一個會員單獨和她待在一起。用瀏覽器在 repo 裡開(她的樣子用相對路徑指到登陸頁的錄影)。頁首中間的虛線小框「示意控制」不是設計的一部分,預設收起;展開後可以切換她在這裡 / 在唱歌 / 睡著了,以及這段對話讓羈絆往上或往下。

## 這頁是做什麼的

現在會員只能在 Discord 頻道裡遇到她,會員頁是帳務後台(魚幣、交易所、點歌、羈絆環),沒有「和她在一起」的地方。這頁補上這件事。

版面照 owner 的方向(2026-11-28):**靜下來時畫面上只有她、她的一句話、一條輸入膠囊**,其他都退到旁邊。

- **她**:置中占滿整個畫面,桌面和手機都一樣,沒有側欄。
- **她的一句話**:直接寫在膠囊上方,不包框、不加名牌;只有舞台下緣一層很淡的漸層讓字讀得清楚。回覆前先「她在想」,然後逐字出現;開著她的聲音時,句尾有一個念的指示。你剛送的那句以小字淡淡顯示在她的話上面,她說完幾秒後淡掉。
- **長的回覆分段**:只有她的回覆超過一段時,句尾才出現一個往下的小箭頭;點她的話、或在空白的膠囊裡按 Enter 換下一段。不需要時什麼都看不到。
- **膠囊**:一條圓頭長條,就是輸入框:開頭一個很淡的「+」附加圖片和檔案,接著提示文字和你打的字,尾端的送出;中間幾個很淡的小圖示是紀錄(只在桌面)、麥克風和她的聲音。桌面最寬 720 px、置中;手機左右各留 12 px,在安全區上方。
- **附加**:附加的圖片(小縮圖)和檔案(名稱、大小)是膠囊上方的小標籤,各有 × 可以拿掉,膠囊本身不變高;手機上兩個並排。把檔案拖到頁面上時,整個舞台出現一圈淡淡的虛線和「放開就附加給她」。送出後紀錄裡那一句下面寫著附加了什麼。
- **字讀得清楚**:她的話和你的那句底下有一條全寬的暗帶,從上方 64 px 淡入;舞台下半部再整體淡淡變暗。就算背後是她最亮的白色絲襪,你那句淡字也在 7:1 以上、她的話在 14:1 以上(1440、1280、375 都量過)。
- **紀錄(backlog)**:雙方的話、時間、羈絆變動發生的位置都在裡面。桌面從膠囊左端的小圖示打開,也可以按 PageUp 或滾輪往上;手機從膠囊往上滑(膠囊上方有一條細把手)。紀錄蓋在舞台上、她淡淡透出來;按關閉、Esc,或在紀錄頂端往下滑就關掉。
- **關係**:右上角一個小羈絆環,會員看不到數字。這段對話讓她提了羈絆時,環下方出現 `+` 或 `−` 和她引用的理由(來自 `<feel>`),愛心跳一下或暗一下,過幾秒淡掉;紀錄裡留著。點環才打開第二層:分級、她寫給你的一句話、她記得的三件事(可以展開、問她這件事、請她忘掉)。
- **狀態**:左上角一行字,其他不加東西。在這裡時是心情和小表情、「也在『雜談』跟大家聊」;唱歌時是唱哪首和「去聽」,膠囊的提示變成「她在唱歌,只會簡短回你」,聲音鍵拿掉;睡著時是「睡著了 · 平常九點左右醒」,畫面變暗,同一條膠囊變成「留話給她,醒來會讀」,麥克風和聲音鍵拿掉。
- **小字**:她是 AI 角色、這裡跟私訊一樣不外傳、她記得的可以刪,寫在紀錄和第二層的底部,不在主畫面上。

刻意不做的:不做數值儀表板、不做每日任務或連續登入、不讓會員改她的個性或外表、不給「好感 +3」的數字(H2:數字會被拿來刷)。

## 這頁逼出來、要 owner 決定的事

1. **私密還是會被提起?** 示意圖寫成「跟私訊一樣」(人設本來就規定私訊不外傳,`<feel>` 在私訊裡也另外標記)。也可以讓她在伺服器裡自然提到「昨天小澄跟我說……」,比較像一個共享的角色,但會員要知道。
2. **文字、語音,還是兩者?** 示意圖兩者都有。語音要每個會員一路 TTS,和她在語音頻道說話搶同一個 worker;要不要限額(AI 額度、魚幣)?
3. **這裡說的話動羈絆的幅度是否和 Discord 一樣?** 一對一很容易刷;可能要比照私訊、或每日上限更低。羈絆往下(被鬧)是否照常?
4. **她忙的時候怎麼辦?** 示意圖:唱歌時只簡短回、只打字;睡覺時只能留言,她醒來讀,回不回由她。另一個選項是忙的時候整頁關門。她的「睡覺」目前只是仲裁器的安靜時段(`quiet_hours`),不是一個對外的狀態。
5. **一次幾個人?** 她是一個角色。35 人同時開這頁,是每個人都有一個「她在這裡」,還是她一次只在一個房間、其他人看到「她在跟別人聊」?示意圖選前者,並寫出她同時在別處。
6. **這頁放在哪?** 會員區的新分頁(`/me/her`),還是 `/watch` 直播頁旁的獨立頁。
7. **「請她忘掉」一件事要多細?** 目前後端只有「全部忘記」和 Discord 的關鍵字 / 單則訊息忘記。

這個版面另外帶出來的:

8. **長回覆要不要分段?** 示意圖把她的長回覆分成兩三段,一次只顯示一段、要點一下才往下(像視覺小說)。另一種是整段一次出現、太長就縮小字或捲動。分段要她(或程式)決定在哪裡斷句;語音照段落念,還是整段念完?
9. **畫面上只留她最新的一句,夠不夠?** 想看前文就要打開紀錄。會員剛送的那句只淡淡出現幾秒;要不要一直留著?
10. **羈絆變動要多顯眼?** 示意圖只在角落出現幾秒、紀錄裡留著。也可以完全不即時顯示,只在第二層和紀錄裡看得到,減少「為了加分而說話」。
11. **這頁的字級**:她的話是 18 px(手機 16 px),超過面板的 15 px 上限;這頁是「和她在一起」不是操作工具,建議當作像登陸頁一樣的例外,要 owner 認可。
12. **她看得懂什麼附加?** 圖片要她的模型看得到圖(視覺能力、額度);檔案要決定接受哪些類型和多大、要不要像 Discord 一樣過審核、存多久、算不算「她記得的事」(能不能請她忘掉)。

### 和 AI 女友 app 的差別

相同:一對一、她的形象占滿畫面、可以語音、她記得你、關係看得見。不同,而且是故意的:

- 她不是你的。她有自己的心情和生活,會在唱歌、會睡覺、會在別的頻道,也不會為了你改設定或外表。
- 羈絆只改變她說話的語氣(擦邊玩笑可以,沒有性內容),不解鎖內容、不買得到。
- 她可以不高興:被鬧會冷下來,羈絆會往下,畫面照實顯示。
- 沒有每日登入獎勵、沒有「她想你了」推播、沒有付費加速。

## 後端:已經有的和缺的(都讀過程式確認)

已經有的:

- **會員登入**:Discord OAuth 的會員 session,`GET /api/member/session`(`packages/api/src/member.ts`)。
- **關係的資料**:`GET /api/member/me` 給分級、下一級、進度和環(`publicBond`,只給圈數和二十分之一的填充,沒有數字)、信任和熟悉的文字分段、她寫給會員的那句話(`public_feeling`)、最多 30 件她記得的事(文字、種類、日期)。被封鎖的人拿到陌生人的答案。
- **忘記**:`POST /api/member/forget` 是全部忘記;記憶引擎的 `forget(person, account, keyword)` 支援關鍵字(`packages/memory/memory/src/engine.ts`);Discord 有「不要記住這則訊息」的選單。
- **私訊情境**:`ContextKind` 有 `dm`,私訊裡的 `<feel>` 已經另外標記、每晚的整體反思不讀(`docs/design/v5-heart.md` §2.12)。`platform: "web"` 已經被檔案連結拿來做審核用的情境(`packages/api/src/files/links.ts`),但沒有人在那裡說話。
- **`<feel>` 和羈絆變動**:每次變動是 `heart.changed`,帶她引用的理由;這就是 `+` / `−` 旁邊那句話的來源。
- **她現在在做什麼**:`GET /api/public/status` 的 `singing / playing / live / in_voice / idle / offline`;唱哪首在 `/api/public/songs`。
- **逐字出現的她的話**:直播頁 `/watch` 已經有她的話邊說邊出現、帶游標;會員的推播流(`packages/api/src/push/`)可以加新 topic。
- **語音**:TTS worker 的 `POST /tts` 是串流的(`workers/tts/server.py`),Core 端有客戶端(`packages/voice/speech/src/tts.ts`)。
- **Live2D 在瀏覽器**:卡片的 card studio 用 Live2D 官方 Web Framework 在無頭瀏覽器裡畫她(`tools/card-studio/src/studio.ts`,由 `packages/play/cards/src/live2d.ts` 呼叫),所以載入模型、設表情和參數的程式已經有。

缺的:

- **網頁上和她說話的入口**:沒有會員送一句話給她、拿回她串流回覆的 route;要一個新的情境(例如 `web:dm:<person>`)、輸入審核、速率和 AI 額度,和她那邊把它當私訊處理。
- **附加**:會員頁沒有上傳圖片或檔案給她的 route;Discord 那邊的附件處理(`packages/types/src/platform.ts` 的圖片類型判斷、附件轉成文字)可以參考,但網頁要自己的上傳、大小限制和審核。
- **分段**:回覆串流目前不帶段落;要她或程式標出斷點,前端才知道在哪裡停。
- **留言**:睡著時留的話,醒來後交給她讀的佇列。
- **對外的心情**:會員 API 刻意不給情緒;要決定能不能給一個詞(「得意」「不耐煩」)。
- **對外的羈絆變動**:`heart.changed` 只在管理端;要一個只給本人、只有方向和她的引用的 topic。
- **紀錄**:會員看得到自己和她的完整對話,要一個只給本人的讀取 route(目前會員頁只給每天的句數)。
- **單件忘記**:會員 API 給的記憶沒有 id,不能只刪一件。
- **睡覺狀態**:`PublicState` 沒有 `asleep`;安靜時段只擋她主動說話。
- **會員聽得到的聲音**:TTS 現在只送進 Discord 語音;要一條把音訊送到瀏覽器的路,和額度。
- **Live2D 在會員的瀏覽器即時跑**:card studio 是在主機上離線算圖,而且 Live2D 的檔案(`vendor/`)和模型都不在 git、「模型不離開這台機器」。把模型送到每個會員的瀏覽器,要先確認模型作者的使用規範和 Live2D 的授權;不行的話,只能放預錄的循環(像示意圖借用的 `apps/panel/src/pages/public/landing/her/` 錄影)或從主機推畫面。錄影裡沒有閉眼的姿勢,所以睡著時用變暗的靜態畫面代替。
