# V5 規劃:一個她、一份契約、每台電腦一個管家

> 狀態:**owner 已回答 §16 的決定**(2026-11-14)。還沒有開始實作,也沒有動任何資料。依據:這次的五份程式碼 review(平台與營運、大腦、互動與經濟、身體、面板與 API,全部是讀程式,沒有執行)和六份外部調查,整理在 [v5-research.md](v5-research.md)。前一版見 [v4-plan.md](v4-plan.md)。文中的行數、筆數來自 review 的靜態統計,§18 列出沒驗證的事。

## 0. 一句話結論

V2 到 V4 每一版都在修「對話」,沒有一版修「系統的形狀」。repo 從 2026-11-01 起兩週 814 個 commit,蓋在一份 Rust 原型的逐行移植上,V2、V3、V4 三套設計同時留在 `main`。所以每加一個功能都要改 `types`、`store`、`api`、`core` 四個地方,每台電腦都要整份安裝,服務彼此的位址靠手抄。

V5 做七件事,前三件是地基:

1. **一份契約、一個登記處**:平台、worker、遊戲、渲染器、擴充都是「能力的提供者」,用同一份 schema 向 Core 報到。Core 不再認識任何功能。
2. **每台電腦一個管家(hostd)**:一個指令裝這台要的服務、一個指令全部啟動、一個指令加入別台的 Core。位址不再寫進設定。
3. **整併**:`packages/` 底下 45 個套件收成 20 個,V2 管線和重複的層刪掉,設定只有一份 schema,資料庫重開。
4. **大腦**:一個決定者(Self loop)。程式只管護欄和成本,要不要說、說什麼、做什麼都在同一次模型呼叫裡決定,拒絕會回給她看。把 harness 給模型的東西給她:足夠的思考、留得住的對話和工具紀錄、找得到的工具、子代理。
5. **心**:羈絆為主,加八個細分數值和文字印象。變動由她提出、程式限速,每一筆都有原因。面板用環狀進度顯示。
6. **玩**:卡照 owner 的企劃分成每日卡和生圖卡,每日卡先做,生圖卡等模型選定;經濟補上去處;每個互動都要有看得見的下文。
7. **很多地方**:Space / Room / Session 取代寫死的 guild,先把 Discord 的多伺服器、多頻道做完整;第二個平台和直播聊天室暫緩。

身體(遊戲、舞台、唱歌)改用同一份能力契約,放在最後一個階段。

### 1.2 要留的

這些是好的,V5 搬動但不重寫:

- **kernel**(1.9k 行):模組介面、依相依順序啟動、退避重啟、健康檢查、service registry、有界的事件匯流排。
- **訊息型別**:`AccountRef`、`ContextKey`、`IncomingMessage`、`PlatformSinks`、帳號連結。終端機聊天和遊戲內聊天已經證明它載得動第二個平台。
- **節點連線**:節點對外撥入、帶版本的 hello 和能力清單、型別化的關閉碼。
- **worker 契約**:`/health`、`/offload`、模型在子行程裡(VRAM 真的還得回來)、fake worker 加契約測試。
- **GPU 讓位**:NVML 讀可用記憶體、學到的各階段峰值、有租期的 offload。這是整個 repo 做得最好的一塊,只是寫成三個 worker 之間的私下協定。
- **護欄**:主人規則(失敗時拒絕)、風險分級加核可卡、緊急停止、輸出審查、資料與指令分開的包裝、「只有真的送達才算說過」。
- **語音**:barge-in(非焦點的人壓低、焦點的人暫停,再由 ASR 決定停或續)、每人一條 VAD。
- **V4 的提示詞順序**、情緒引擎的動態、有她自己立場的人物卡、模型路由和逐次呼叫檢視器。
- **帳本**:只增不改、冪等鍵、託管、兩列轉帳。
- **CLI 的內部**:可重複執行的 install、`doctor --deep`、到處都有 `--dry-run`。它的角色模型是 hostd 的種子。
- **公開面的安全**:回應逐欄組出來並有測試釘住、PKCE、只存 session 雜湊、被封鎖的人看起來和陌生人一樣。

## 2. 原則

1. **一件事一個主人**:一個決定者、一份契約、一個登記處、一份設定 schema、一份事件紀錄、一套卡片。
2. **程式管護欄和成本,不猜她想要什麼**。上限擋下來時,拒絕是一個她看得到的工具結果,不是默默丟掉。
3. **Core 不認識功能**。功能是外掛,自己帶資料表、路由、指令、提示詞段落和設定 schema。
4. **位址不寫進設定**。服務啟動後自己報到,模組要的是「asr」不是網址。
5. **契約只寫一次**,TypeScript、Python、面板、SDK 都從同一份 schema 產生。
6. **數字是她感受的結果**。她提出變動和原因,程式限速、記錄。
7. **互動要有下文**:抽到的卡能放、能用、能送;她收到東西會記得。
8. **先能量測再刪**:補丁和規則一條一條拿掉,每條都過真模型評測。
9. **新舊不並存**:每個階段結束時,被取代的那條路要刪掉。

## 4. 契約與登記處

**`contracts` 套件**用 zod 寫 schema,產出 JSON Schema,再產出 TypeScript 型別、Python worker 用的 pydantic 模型、SDK 型別、API 路由表和面板型別。現在手抄的 voice-link(兩份)、SDK 型別、面板的 `api/types.ts`(2385 行)都由它取代。

**事件信封**:`{ type, data, id, parent, at, turn, source }`,`source` 由 Core 蓋章,接收端不用相信自稱。控制訊息走信封;音訊照舊走獨立的二進位通道。

**能力**(provider 報到時宣告的東西):

| 種類 | 例子 | 今天在哪 |
|---|---|---|
| `channel` | Discord 文字、Telegram、OneBot | `packages/discord` |
| `ingest` | Twitch / YouTube / Bilibili 聊天室 | 沒有 |
| `voice-room` | Discord 語音(self 帳號) | `apps/voice-node` |
| `asr` · `tts` · `turn` · `embed` | Python worker | `workers/*` |
| `sing` · `imagegen` | 排隊型的 GPU 工作 | `workers/sing`、ComfyUI |
| `renderer` | VTube Studio、overlay,以後的 VRM | `packages/stage` |
| `activity` | Minecraft、osu、Neuro SDK 遊戲、派對遊戲 | `packages/game`、`extensions/*` |
| `tool` | MCP、擴充的工具 | `mcp`、`ext-host` |
| `panel` | 外掛自己的面板頁 | 有寫沒做 |

**提供者的接法**有三種,契約相同:Core 行程內的模組;子行程(現有的 stdio JSON-RPC);遠端(同一份 JSON-RPC 走 WebSocket,由 hostd 管)。第三種是新的,它讓遊戲轉接器和擴充能跑在硬體所在的那台電腦。

**登記處**在 Core:能力 → 端點、健康、負載、版本。模組呼叫 `registry.pick("asr")`。提供者報到時帶契約版本和 `requires` 範圍,太舊的會被拒絕並說明原因。搬遷期間 TOML 裡的網址當作靜態後備。

## 5. 多台電腦

### 5.1 名詞

- **Cluster**:一個 Core 和它的角色。
- **Host**:一台跑著 `miyoria-hostd` 的電腦。
- **Service**:hostd 管的一個單位(core、voice-node、stage、asr、tts、sing、turn、lyrics、embed、mediamtx、comfyui、一個擴充或遊戲轉接器)。
- **Capability**:服務提供的能力(§4)。

### 5.2 服務描述檔

每個服務的資料夾放一份 `service.toml`,取代寫死在 `roles.ts` 的七個名字和三種角色:

```toml
name = "asr"
provides = ["asr"]
platforms = ["win32", "linux"]

[install]
python = "3.12"
lock = "uv.lock"                 # uv sync --frozen
models = [{ repo = "Qwen/Qwen3-ASR-0.6B", revision = "<pinned>" }]

[run]
command = "python server.py"
port = "auto"                    # hostd 分配並回報,不再有三個預設值
health = { http = "/health", startup_s = 120 }
restart = { policy = "on-failure", backoff_s = [1, 5, 30] }
guard = []                       # 例:voice-node 寫 ["live"],core 寫 ["singing"]

[gpu]
policy = "pinned"                # pinned:常駐,不等租約;on_demand:用時才載
vram_mb = { resident = 2500, peak = 3000 }
unload = "http:/offload"
```

OBS 和 VTube Studio 標成 `interactive`:在使用者的桌面 session 啟動,只探測,不自動重啟。

### 5.3 hostd 做什麼

- 依 `host.toml`(這台的名字、Cluster 網址、裝了哪些服務、本機路徑)安裝和執行服務:TS 服務用 `pnpm deploy` 的相依閉包,Python 用 uv,模型照描述檔下載。只跑 worker 的電腦不需要整個 repo。
- 重啟策略、健康探測、輪替的日誌檔。重啟前先問 Core 現在安不安全(正在唱歌、正在 Go Live 時不重啟帶 `guard` 的服務),這回答了 backlog 裡「自動重啟會不會打斷直播」的問題。
- **VRAM 仲裁**:把現在 sing 對 tts、asr 的 `/offload` 協定收進 hostd。預算是顯卡記憶體減掉留給 OBS 和 VTS 的量;`on_demand` 服務用完閒置後被收回,`pinned` 不會被動。排隊中的唱歌或生圖請求會變成她說得出口的「等一下」。
- 一條對 Core 撥出的、有認證的 WebSocket:回報服務、端點、健康、GPU,接受啟動、停止、更新。
- 開機啟動:Windows 用登入時的排程工作(OBS、VTS 需要桌面 session),Linux 用 systemd。

### 5.4 加入和連線

```
miyoria host invite            # 在 Core 那台或面板上:產生一次性的代碼(10 分鐘)
miyoria host join https://core.example:7878 --code ABCD-1234
miyoria add asr tts            # 這台要裝什麼
miyoria up                     # 啟動這台裝的全部
```

代碼換成這台專屬的金鑰;這台宣告的能力要在面板上另外核可一次。之後每個 worker 呼叫都帶這台的 token,沒有任何服務裸奔在區網上。

- **自己的電腦之間用 Tailscale**(MagicDNS 名稱、用 tag 限制誰能連哪個埠)。即時的 ASR、TTS 直接連。
- **別人的電腦不進你的 tailnet**:hostd 只對外撥一條 WSS,Core 經這條線下工作。延遲比較高,適合唱歌和生圖這種排隊型工作,不適合即時語音。

### 5.5 CLI

| 指令 | 做什麼 | 今天 |
|---|---|---|
| `init` | 問這台要做什麼,寫 `host.toml` | 有,改寫 |
| `host invite / join / ls / approve / remove` | 加入和管理電腦 | 沒有 |
| `add / remove <service>` | 裝或移除一個服務 | 只有固定角色的 `install` |
| `up / down / restart [service]` | 交給 hostd | `up` 前景、`start` 開分頁,沒有 stop |
| `status [--all]` | 這台或所有電腦的服務、健康、版本、VRAM | 只讀 Core 的 API |
| `logs <service> [-f] [--host]` | 輪替的日誌 | 沒有 |
| `doctor [--fix]` | 現有檢查加上 hostd、連線、token | 有 |
| `update` | 只重裝 lock 變了的服務,一次重啟一個,帶 guard | 有,不會重啟 |

### 5.6 設定分成四份

1. **Cluster 設定**存在 Core(資料庫、有版本),由外掛的 schema 組成一份總 schema,改了不用重啟。大部分數字收成具名的預設組(例如話多話少選一個檔位,不是調四十個數字)。範例檔、文件裡的表、面板的表單都從 schema 產生。
2. **Host 設定** `host.toml`:不含任何別台的位址。
3. **祕密**:各台自己的放在各台;LLM 金鑰和 Discord token 只在 Core,worker 需要時經連線向 Core 要(lyrics 不再自己讀 `miyoria.toml`)。
4. **角色包**:只有人設和素材。

### 5.7 自己寫 hostd,還是用現成的

外部調查建議 process-compose(健康探測、相依順序、重啟、TUI 都有),風險是它在 Windows 上最少人測,而且由一個人維護。review 建議自己寫。**我建議自己寫**,理由:重啟要懂「現在不能打斷」;VRAM 租約要和啟停綁在一起;OBS、VTS 只探測不重啟;現有的 kernel Supervisor 和 CLI 的 `stack/*` 已經有七成零件。描述檔保持和監管程式無關,之後要換或要產生 systemd unit 都可以。

**決定(2026-11-14):自己寫。**

## 6. 一個她,很多地方

**實體**:

- **Person**:一個人。**Account**:某個平台上的帳號,連到 Person(現有的帳號連結;新平台用一次性代碼綁定)。
- **Space**:一個伺服器或群組。**Room**:裡面的一個頻道、討論串或語音房,帶能力旗標(可語音、可按鈕、可貼圖、可討論串)。
- **Session**:她在一個地方的對話脈絡,鍵是 `<platform>:<space>:<room>[:thread]`,私訊是 `<platform>:dm:<person>`。另有一個不屬於任何地方的 **home** session,是她自己的生活。

**範圍**:

| 東西 | 範圍 |
|---|---|
| 羈絆和各項數值、人物文件、卡片、錢包 | 每個 Person,跨平台、跨 Space |
| 記憶 | 帶對象標籤:私下的記憶不會載入群組的提示詞 |
| 伺服器目標、商店、房間、點歌佇列、每日貼文、時區、掉落開關 | 每個 Space(今天全是單例) |
| 話多話少、能用的功能、語言 | 每個 Room,繼承 Space |

**平台外掛的契約**:連線、送出、編輯、反應、輸入中,加上能力旗標。指令、選單、表單在 `interaction` 套件裡是抽象的 UI,各平台自己畫;沒有斜線指令的平台退回文字指令。網域程式碼裡不再有 `"discord"` 預設值。

**群組裡的行為**:房間裡每一句都是脈絡,她只有呼叫 `say` 才會出聲。每一行帶穩定的說話者 id 和「是不是對她說」的旗標;偽造說話者行的訊息在進提示詞前標記。別的地方發生的事,以合併過的通知進 home session,要看細節用有權限檢查的讀取工具,不合併逐字稿。

**直播聊天室**是一種 `ingest`:先過濾(洗版、注入、重複),再計分,緩衝到她一句講完時給一份摘要;付費訊息不會被丟,走優先道,在她講完當前這句後插入。觀眾先是沒有 Person 的 Account,綁定後才有羈絆。

**決定(2026-11-14):第二個平台和直播聊天室暫緩,先把 Discord 做完善。** Space / Room / Session、每個 Space 的設定、拿掉網域程式碼裡的 `"discord"` 預設值仍然要做,多伺服器需要它們。平台外掛的契約留在設計裡,要接第二個平台時再實作。

## 7. 大腦

### 7.1 Self loop

```
事件 → 收件匣(事件紀錄,先寫入再處理)
     → 分流(程式):被叫到一定叫醒她;結果、計時器、世界事件叫醒她;
                    沒人叫她的閒聊合併成「看一眼」,每個地方每小時最多 N 次
     → Self 回合(一條模型呼叫鏈):看同一份脈絡,決定說不說、說什麼、做什麼
     → 工具:say(place, …) · react · dm · recall · delegate · schedule · …
     → 護欄:主人規則、發言上限、預算、審查、核可、送達帳本(拒絕回給她)
```

- 分流只決定**何時叫醒、看哪裡**,是成本上限,不是個性。擲骰、注意力計分、Plan → 提案 → Arbiter → 主線這條鏈、重複的願望篩選都刪掉。
- 回應別人和她自己找事做是同一個代理、同一組工具。主動的回合是「沒人在說話、這是你的收件匣」的視角。
- 語音被直接叫到時仍然直接進回合,思考關閉、前綴相同,只有尾端不同。
- 一個回合跑者,四種設定檔:語音(2 輪、極少工具)、文字(約 10 輪)、子代理(長)、反思(每晚、高思考)。現在的主線、V2 迴圈、work lane 三套收成一套。

### 7.2 提示詞版面(為了前綴快取)

| # | 區塊 | 變動 |
|---|---|---|
| 1 | 人設核心、輸出約定、用工具的規矩(短,用她的語言) | 不變 |
| 2 | 約 15 個常駐工具 + `find_tools` + `skill`,順序固定 | 部署時才變 |
| 3 | 主人規則;她自己寫的「我最近是誰」 | 每天 |
| 4 | 這個地方的摘要 + 常客的人物卡 | 壓縮或名單變動時 |
| 5 | 逐字稿,**包含她真的工具呼叫和結果**,會壓縮 | 只增 |
| 6 | 這次取回的記憶、收件匣(結果、別處的事) | 每回合 |
| 7 | `<now>`:狀態、情緒、活動、有期限的承諾 | 每回合 |

工具能不能用由護欄在呼叫時判斷,不靠把工具從清單拿掉(那會打破快取)。

### 7.3 工具、技能、子代理

- **一個登記表**。每個工具帶副作用類別(讀 / 說 / 做 / 花錢 / 對外)、快慢、風險等級。MCP 工具預設也有風險等級。
- **漸進揭露**:經濟、派對、唱歌、遊戲、直播這些工具經 `find_tools` 找到或由技能帶進來。`skill(name)` 在回合內就能打開。
- **迴圈**:唯讀呼叫並行;長動作回傳一個工作代號,完成時是收件匣裡的一個事件,她帶著完整的逐字稿接著做。
- **子代理** `delegate(kind, goal, budget)`:research(查網路)、coder(沙箱)、game(導演)、curator(整理記憶)、reflect(每晚)。同時兩三個,有每日 token 預算。子代理不能說話、不能花錢,只回傳摘要和產物。讀外部內容的子代理沒有任何有副作用的工具。
- **排程**:她可以 `schedule` 自己之後醒來;時間到是收件匣事件,走同一條回合。

### 7.4 記憶

| 層 | 內容 |
|---|---|
| L0 | 事件紀錄,唯一的原始資料;訊息、決策、回合紀錄都從它導出 |
| L1 | 每個地方的逐字稿,落地保存,會壓縮;壓縮前先把值得留的寫進 L2、L3 |
| L2 | 情節摘要,本機多語 embedding 加關鍵字檢索 |
| L3 | 筆記本:每個人、每個地方、每個主題和她自己各一份文件。寫的時候看得到現有內容,所以能處理矛盾;取代舊事實用「標記過時」不是刪除 |
| L4 | 關係數值(§8) |
| L5 | 技能和教訓 |

寫回關於人的事實要有對方自己說的話當依據。記憶不會因為人不常出現而被衰減刪掉(MaiBot 踩過這個坑)。

### 7.5 模型

- **決定(2026-11-14):繼續經 OpenCode,全部用 flash。** 階段 0 先驗證它有沒有照做思考開關、有沒有把 effort 送出去;思考的上限不能截斷答案。驗證不過再回來談直連。
- 依用途只分思考量:

| 用途 | 思考 |
|---|---|
| 語音回合、看一眼 | 關或最低 |
| 文字回合 | 真的 effort 設定 |
| 子代理、反思 | 高 |
| 評分(情緒、關係變動的檢查) | 低,結構化輸出 |
| 視覺 | 現有的 provider |

- **預算:每天 10 美元。** 每個 session 也有上限;超過時下一個請求不送出,面板看得到當天花了多少。
- embedding(把文字變成一串數字,讓記憶能用意思而不是關鍵字找)今天關著。它是她已有的記憶檢索裡「怎麼找」的那一步,不是新功能。repo 已經支援兩種接法,換模型只要改設定:`provider = "local"`(Node 裡用 transformers.js 在 CPU 跑,預設 `multilingual-e5-small`)和 `openai-compatible`(Ollama、LM Studio 這類本機服務)。
- 候選(2026-11-14 查的;分數是各家自己公布或第三方轉述的多語 MTEB,沒有對過排行榜,授權以模型頁為準):

- 每次模型呼叫都落地保存,能從事件紀錄重建當時模型看到的一切。

### 7.6 主動

機會(計時、世界事件、想念)→ 程式的閘門(安靜時段、每日額度、冷卻、預算)→ Self 回合(她可以決定不說)→ 送達回條。沒人回她時間隔自動拉長,有人回就重置;同一類目的不連續出現;送達結果不明的不重送。面板上有一個總開關能讓所有主動來源安靜。

### 7.7 評測

刪任何補丁之前先有真模型評測,每晚跑、畫趨勢:人設評審(在角色裡、溫度、簡短、不洩漏)、用 owner 資料庫標註的記憶 recall@k、十個假世界工具任務的成功率、關係一致性探針。

### 7.8 和 harness 的對照

| harness 給模型的 | 今天 | V5 |
|---|---|---|
| 長的迴圈 | 3 輪 | 文字約 10 輪,重的交給子代理 |
| 留得住的逐字稿和工具紀錄 | 160 字痕跡,重啟就沒 | L1 落地 + 壓縮 |
| 找得到的工具 | 85 個 schema 一次全給 | 15 個常駐 + `find_tools` |
| 回合內可用的技能 | 看得到名字 | `skill(name)` |
| 子代理 | 一個通用 worker,一次一個 | 五種,並行兩三個 |
| 思考預算 | 2048 token 含答案 | 真的 effort,依用途分流 |
| 沒人改它的輸出 | 20 個補丁 | 過評測後逐一刪除 |
| 壓縮、記憶檔、排程喚醒、hooks | 無 / 部分 | L1 壓縮、L3 文件、`schedule`、護欄即 hooks |

另一條可選的路:需要寫大量程式的工作,讓 coder 子代理在沙箱裡驅動一個真正的 harness(DeepSeek Harness 的 `sdk` profile 是 JSON-RPC)。它還在 developer preview,先做小試驗再決定。**不**建議把整個大腦搬到別人的 harness 上:即時語音、多使用者的公開場合、前綴快取都需要自己掌握回合。

## 8. 心

### 8.1 她自己的情緒

情緒引擎留著。說話的那次模型呼叫多輸出一個不顯示的 `feel` 欄位(此刻的情緒和強度);程式套用現有的增益和衰減。今天是 120 秒後另一次呼叫替她選,說話的她碰不到自己的情緒。情緒再變成參數:回覆快慢、長短、用貼圖和反應的機率、主動的意願。

### 8.2 對每個人

| 數值 | 範圍 | 意思 | 怎麼動 |
|---|---|---|---|
| **羈絆** | −100..1000 | 主要的值:有多親 | 由下面幾項慢慢累積;分級要有一段真的共同記憶當錨點 |
| 信任 | 0..100 | 這個人守不守承諾、守不守祕密 | 守信上升;說謊、想套話下降 |
| 熟悉 | 0..100 | 她知道對方多少、分享過多少 | 只增,久了變模糊但不歸零 |
| 好感 | −1..1 | 此刻對這個人有多暖 | 快;往羈絆決定的基準回落 |
| 敬意 | −1..1 | 佩服對方的本事、善意、品味 | 贏了她辦的遊戲、幫了別人 |
| 自在 | 0..1 | 在這個人面前多放鬆(決定傲嬌遮多少) | 相處時間、沒被取笑 |
| 心結 | 0..1 | 還沒解開的委屈 | 會淡,但要道歉、禮物或一起玩才真的解開;高的時候她會冷一陣子 |
| 想念 | 0..1 | 多久沒見 | 不在時上升 |
| 默契 | 0..1 | 鬥嘴合不合拍、有沒有共同的梗 | 接得上的玩笑 |

另有文字欄位:她對這個人的立場、印象、還沒聊完的事、彼此的承諾、共同的梗、她不喜歡對方的地方。往來(誰給了誰什麼)直接從帳本算,不另存。

### 8.3 規則

- **她提出,程式限速**。每回合她可以在 `feel` 裡對在場的人提出小幅變動,附一句引用當原因;程式套上限、每日上限、負面約三倍、不對稱和衰減。每一筆變動都記下來,面板看得到「為什麼」。
- **所有互動都是證據**:語音相處、聽她唱歌、一起玩、任務、禮物、卡片都進同一條管線讓她看到,不是各自固定加幾點。
- **每晚反思**一個人一次:讀當天的事和現有文件,改寫文件、核對數值。
- **羈絆改變的是語氣和主動,不是門檻**:稱呼、會不會私訊、進語音時的招呼、願意說多少自己的事、里程碑卡、「看一眼」時先看誰。不改價格、不改機率,也不改她拒絕什麼。
- 羈絆不會被買到:禮物只是一點點,現有的規則留著。
- **節奏(決定,2026-11-14)**:每天都來的人大約六個月到最高級(1000),前面幾級快、後面慢。高分級除了點數還要一段共同記憶當門檻。久沒來會掉,但只掉到已經達成的分級為止。

### 8.4 顯示

- **管理面板**:一頁人物總覽(現在重疊的兩個清單合併)。每個人一個**環狀進度,中間一顆愛心**:環是目前分級內的進度,刻度是分級邊界,旁邊是確切數值;八個細項用小弧或長條;下面是變動紀錄和她寫的文件。
- **公開頁和 Discord**:同一個環,顯示分級名稱和到下一級的進度,不顯示數字、不排名(v3 §17.1;owner 2026-11-14 確認)。
- 現有的 `Bipolar` 超過 100 就畫滿,在新頁面完成前先修(§15 階段 0)。

## 9. 玩

外部市場的訊號:中文社群裝最多的是貼圖(19 萬)、主動搭話(14.6 萬)、記憶(11.5 萬)、群聊讀空氣(10 萬);遊戲、抽卡、純好感度外掛只有幾百到幾千。也沒有任何專案把經濟或抽卡和關係綁在一起。所以順序是:先讓她會用貼圖、會主動、記得人,再做遊戲;而「卡片是你和她的回憶」是別人沒做的。

### 9.1 卡片

細節在 [v5-play.md](v5-play.md);底子是 owner 的 [image-cards.md](image-cards.md)(2026-11-12)和 [cards.md](cards.md)(2026-11-09)。底線不變:沒有真錢、機率公開、稀有度不是羈絆、表情由關係決定。

### 9.2 生圖

## 10. 身體

- **活動契約**:提供者宣告動作(名稱、說明、JSON schema)、脈絡通道(可就地取代)、它是哪一種(導演式 / 強制選擇式 / 只有工具)。活動種類變成登記的資料,`ActivityType` 不再是封閉 union,導演的目標模型可以抽換,`obtain` 搬回 Minecraft 自己那邊。
- **內建一個 Neuro Game SDK 伺服器端點**(startup、context、register、force 加優先級、result 逾時、speech 開始 / 結束),轉到內部匯流排。任何已經支援它的遊戲就能直接接;現有的 `extensions/neuro` 接進契約。
- **反射留在活動那一側**:即時遊戲裡模型只下意圖,快的事由轉接器或 mod 自己做,她只看摘要。有動作佇列上限、無動作預算、失聯逾時。
- **技能是資料,不是程式**:基本動作,加上檢索得到的「動作序列加前置條件」,成功過才存。不讓模型寫可執行的遊戲程式(owner 的 Minecraft 設計:風險高、直播不穩)。

- **舞台**:把「表演者」(情緒 → 表情意圖、姿勢、眨眼、嘴型)和「渲染器」(VTube Studio)分開。overlay 的資料流已經是中性的,以後的 VRM 或瀏覽器 Live2D 吃同一份。表情名稱從渲染器問來、放進提示詞,文字裡的動作標記在那一段聲音播出時觸發。
- **輸出佇列**:說話、唱歌、音效是帶優先級的工作,即時的話可以搶在唱歌前面。被打斷時只記對方真的聽到的部分。

## 11. API、面板和檔案

### 11.1 API 和面板

- **路由表在 `contracts`**:每條路由宣告請求和回應的 schema、認證方式、權限。面板直接 import 型別,三份抄本刪掉;回應也驗證。
- **三組路由、兩個綁定**:管理 API 只綁本機或 tailnet;公開加會員的 API 綁隧道;hostd 的控制連線另外一組。管理 token 加失敗次數限制。靜態檔用允許清單(現在 `dist` 裡的 `*.local.*` 圖可能被公開送出,先確認)。
- **外掛自己貢獻路由**,`http` 只是殼(認證、session、SSE、送面板)。
- **面板拆成 `apps/admin` 和 `apps/web`**,共用 `packages/ui`(token、玻璃、圖表、環)。輪詢改成 SSE 的快照加增量。新增「電腦」頁:每台的服務、健康、版本、VRAM、日誌尾巴、啟停。人物頁見 §8.4。
- 建置只留一個安全的指令(現在只有 `miyoria update` 帶防毒的繞過參數)。

### 11.2 她做出來的檔案

今天她做得出檔案,交不出去:工作區的檔案只有她自己讀得到,生圖的結果沒有出口,平台型別裡的附件只有「收進來」。委託、底片、時刻卡、子代理寫的報告和程式都需要一條出路,而且每個平台的附件能力不一樣。

**產物庫**(`store` 裡的基礎設施,所有外掛共用):

- 一個產物是一份不可變的內容加一筆紀錄:id、sha256、大小、型別(看內容判斷,不信副檔名)、清理過的檔名、來源(生圖 / 沙箱 / 卡片 / 唱歌 / 剪輯 / 文件)、哪個回合做的、為誰做的、可見範圍、到期時間、審查狀態。
- 內容以雜湊為名存在 Core 那台的磁碟,介面之後可以接 S3 相容的儲存。別台電腦做出來的(生圖、唱歌)由 Core 經 hostd 拉進來,取代今天「stage 和 Core 要共用磁碟」的假設。
- 每人、每個 Space、每天有容量額度。預設 7 天到期,放進相簿或按「保留」才留下。面板看得到用量,可以下架。

**怎麼交到人手上**:

1. **分享是一個明確的動作**:工具 `share(產物, 給誰, 多久)`,和 `say` 走同一個出口和護欄。沒被分享的產物在網路上碰不到。
2. 平台收得下就直接當附件上傳,同時附一條連結;收不下或沒有附件能力的平台只給連結。
3. 連結是 `https://<檔案網域>/f/<token>`。token 是 128 bit 以上的隨機值,資料庫只存雜湊,可以撤銷、會到期、記下載次數。可見範圍三種:

| 範圍 | 條件 | 預設用在 |
|---|---|---|
| 本人 | 用 Discord 登入,而且就是那個 Person | 私訊裡做的、關於某個人的 |
| 這個 Space 的成員 | 登入且是成員 | 頻道裡做的 |
| 有連結就能看 | 無 | 本來就公開的東西(卡面、公開直播的片段),或本人自己改成公開 |

4. 公開站的會員區有「她做給我的」:列表、下載、刪除、改可見範圍。

**安全**:

- **只有進過產物庫的東西能分享**。沒有任何工具吃主機上的路徑,所以她分享不了 `.env`、`miyoria.toml` 或資料庫。沙箱本來就拿不到 Core 的祕密,這條不變。
- **可見範圍不能超過產生它的地方**:私訊裡做的不會變成整個伺服器可見,放寬只有本人能做。這和記憶的對象標籤是同一條規則。
- **另一個來源**:檔案從獨立的網域送出,不帶 cookie,和管理面板、會員站分開,惡意的檔案碰不到任何人的登入狀態。只有一個網域可用時退而求其次:一律 `Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`、`Content-Security-Policy: default-src 'none'; sandbox`。
- **型別允許清單**:圖片、音訊、影片、PDF、純文字、zip。HTML、SVG、腳本絕不以瀏覽器會執行的型別送出,只能下載,或由站上的檢視器跳脫後顯示。可執行檔不收。
- **送出前檢查**:文字過現有的祕密遮罩;圖片重新編碼(去掉 EXIF 和藏在圖裡的東西)並過 NSFW 分類;有大小上限。沙箱產出的檔案一律當作不可信內容。
- **id 不是路徑**:查的是資料庫裡的 token,再用雜湊取內容,沒有目錄列表,也沒有路徑穿越。檔名由程式清理,模型給的名字不直接進回應標頭。
- **流量**:每個 token、每個 IP 限速。公開且不可變的內容讓 CDN 快取;需要登入的一律 `no-store`;私人連結不產生預覽。
- **稽核和下架**:每次分享都是事件紀錄裡的一筆(誰要的、哪個回合、給誰)。每個產物頁有檢舉;owner 在面板可以下架和封鎖。
- **不當檔案空間**:只有她產生的東西進得來,使用者不能上傳;zip 只給本人。
- **著作權**:翻唱的成品不開放下載,只在語音和直播裡聽。

風險等級:分享給提出要求的本人是低;分享到頻道是中;改成「有連結就能看」是高,要 owner 核可,或本人自己在網頁上按。

用到它的地方:卡片和相簿(§9.1)、底片、委託交付、coder 和 research 子代理的成品、每週回顧卡、直播片段。

## 14. 安全

- **`boundaries.md` 移除**(owner 2026-11-14 決定)。它是一份寫給單一私人使用者的通用政策,開頭偽造系統訊息,把惡意程式、釣魚工具和更糟的內容列為可做,而它每回合都進一個有程式執行、上網、私訊工具的公開多人 bot。它也是人設被擠掉的原因之一。owner 真正的界線寫成幾句人設,加上已有的程式護欄就夠。V5 的任何部分都不依賴它。
- **她的界線**(owner,2026-11-14):黃色笑話和擦邊可以;不描寫真正的性行為。別人對她開黃腔或騷擾時她怎麼回看羈絆:親近的人她會接、會鬧回去,不熟的人她會擋掉。這條線在每個分級都一樣,羈絆改變的是語氣。對看起來未成年的人不開這類玩笑。
- 一個對外的出口:遮罩、目標允許清單、注入標記都在同一處。她做的檔案也走這個出口,規則見 §11.2。
- 讀外部內容(網頁、聊天室、遊戲文字、字幕)的子代理沒有有副作用的工具。
- 技能是資料:有版本、可復原、寫入要核可、久沒用的封存。不裝別人市集的技能。
- 程式執行靠作業系統層的隔離(容器),核可提示只防手滑。
- worker 有 token;Gateway 不對 loopback / tailnet 以外開放;加入要代碼加能力核可兩步。
- 外掛要明確啟用;不會因為檔案放進某個資料夾就執行。

## 17. 風險和不做的事

- **重寫的範圍**:階段 1 是機械式搬移,不改行為;每一步都要 typecheck 和現有測試全過。行為的改變只在階段 3 之後,而且有評測擋著。
- **hostd 是新的常駐程式**,它壞了整台的服務都受影響。它要小,而且 `miyoria up --foreground` 保留當作不經 hostd 的退路。
- **Self loop 會讓她變得比較吵**。上限是程式的護欄,預設值保守,面板有總開關;話多話少仍然是每個 Room 的一個檔位。
- **token 成本上升**(更長的迴圈、子代理、每晚反思)。靠分流、預算和快取壓住,面板要看得到每天花多少。
- **不做**:Kubernetes 或 Nomad;技能市集;把大腦搬到別人的 harness;語音改走 bot 帳號(owner 已決定);真錢;公開的羈絆排行榜;每日卡的交易和任何卡的買賣;讓模型寫可執行的遊戲程式。第二個平台和直播聊天室是暫緩,生圖卡池等模型,都記在 backlog。
