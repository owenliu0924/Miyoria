# V5 的玩:卡片、生圖、回收、派對遊戲

> 2026-11-14 規劃,沒有實作。底子是 owner 的 [image-cards.md](image-cards.md)(生圖抽卡企劃)和 [cards.md](cards.md)(每日卡的立繪),加上這次唯讀查詢 `data/miyoria.db` 的帳本和行為紀錄。它是 [v5-architecture.md](v5-architecture.md) §9 的細節。標「草案」的數字都還沒定;§8 是 owner 2026-11-14 的決定和還沒定的事。

## 0. 結論

1. **兩種卡都要花魚幣**:每日卡一張 30,生圖卡一抽 150(草案)。
2. **生圖卡整包暫緩到模型選定,但現在就設計完**。和模型無關的部分(資料、抽卡、底片庫、檢查的管線、面板)可以先用現有的 workflow 在旗標後面做好,選定模型後只換 workflow、重新校準、重新審主題。
3. **生圖走 ComfyUI 的 API**,就是現有的 `imagegen`。ComfyUI 跑在哪一台由 hostd 決定,不一定是這張 12 GB 的卡。
4. **回收**:六天裡發出約 6,400、收回約 3,200,收回的一半以上是餵食;十幾種花費幾乎沒人用。做法是刪掉沒人用的,加上會重複發生、規模跟著餘額走的去處:深海交易所(模擬公司的股票)、每週拍賣、每週樂透、點歌優先券、水族箱。
5. **派對遊戲**六天裡一次都沒開過。留猜歌和海龜湯,讓人能自己開;問答和兩種接龍刪掉。

- **內容**:她當下對你的關係的快照(分級、她寫的一句話、印章),立繪用 Live2D 現場算圖;眼鏡、手上的東西、服裝、姿勢、背景這些部件照公開機率隨機配上,不能指定。表情由關係決定,買不到。

- **圖鑑**:收集的是部件。集滿一個系列給稱號。每人一頁,預設只有本人看得到,不排名。舊的收藏品留在圖鑑裡。

## 3. 生圖卡

玩法照 [image-cards.md](image-cards.md),這一節只寫「要蓋什麼」和它接進 V5 的方式。

### 3.1 三種東西

| 東西 | 是什麼 | 主要欄位 |
|---|---|---|
| **主題** | 一個 prompt 模板,不是一張圖 | 卡池(常駐 / 某一週的限定)、稀有度、場景 / 服裝 / 動作 / 光線的範圍、反向提示、workflow 代號、檢查門檻、庫存目標、狀態(草稿 / 樣本待審 / 上架 / 下架) |
| **底片** | 一張生好、檢查過、還沒發出去的圖 | 主題、seed 和參數、各項檢查分數、圖(產物庫裡的一個私有產物)、狀態(庫存 / 已發 / 淘汰) |
| **卡** | 發給某個人的一張 | 流水號、主人、底片、她寫的卡面、稀有度、取得時間、是不是封面、是不是覺醒版 |

另外每人每個卡池一筆保底計數,每人每個主題一格圖鑑。

### 3.2 抽一次

1. 扣魚幣(一抽 150、十連 1,350,一天最多 20 抽;庫存低時上限自動調低)。
2. 抽稀有度(N 70 / R 22 / SR 7 / SSR 1),套保底(30 抽必出 SR 以上;限定池 80 抽必出本期 SR 主題,計數跨週延續)。
3. 在那個稀有度裡抽一個主題。
4. 從那個主題的庫存拿一張底片,綁到這張卡,從庫存移除。一張只發一次。
5. 她看圖寫卡面(幾秒)。這段時間畫面上是底片慢慢顯影。
6. 庫存是空的,或抽到 SSR「和你」:這一抽變成「未沖洗的底片」,先公布稀有度和主題,圖好了私訊通知;24 小時內生不出來就退錢。

### 3.3 底片庫

- 每個主題維持庫存量(草案 N 30、R 15、SR 8),低於門檻就排批次工作補。
- 批次工作只在 GPU 有空時跑:經 hostd 的 VRAM 仲裁,她在唱歌或開台時讓位(現有的 `imagegen` 已經會在唱歌時讓出)。
- 每張進庫前過 §3.4 的檢查,沒過就重生,同一格最多重試 3 次。淘汰率記下來,面板看得到每個主題的數字。

### 3.4 檢查和審核

| 檢查 | 抓什麼 | 做法 |
|---|---|---|
| 像不像她 | 臉跑掉、髮色不對 | 和她的參考圖算圖像相似度,低於門檻淘汰。門檻用每個主題的樣本校準 |
| 壞圖 | 多手指、崩臉、糊 | 臉和手的偵測加美感分數 |
| 不該有的內容 | 暴露、血腥 | NSFW 分類器;主題模板本身先過現有的審查和主人規則 |
| 她自己看 | 圖和主題不合 | 她寫卡面時可以回「這張不像我」,就不發,換一張 |

- **owner 審的是主題模板**:上架前看一組樣本(12 張)。之後面板每天隨機抽幾張底片給 owner 看。
- **SSR 和「和你」**:頭一個月每張都先經 owner 看過才沖洗。
- 卡片頁標明「圖由 AI 生成」,有「這張有問題」的檢舉:先隱藏、退錢、進 owner 的待辦。

### 3.5 抽完之後

- **圖鑑**:每個主題一格,抽到就亮。同主題有好幾張時自己挑一張當封面。集滿一個系列給稱號和卡框。
- **覺醒**:同主題 3 張,拿自己挑的那張當參考,用更高品質重繪;另外兩張消失。草案再收 100 魚幣。
- **分解**:不要的卡變成鱗片;鱗片換「指定主題一抽」(選主題,不選圖)。
- **她的參與**:每張卡的卡面是她看圖寫的;SSR 多一句她的語音;抽到 SR 以上和覺醒她會記得;可以拿卡給她看,一天一次。
- **全服相簿**:只放本人同意公開的,不排名。
- **贈送**:一般卡可以送、不能賣;SSR「和你」不能送。草案:送卡收 20 魚幣手續費,一天最多送 3 張,收的人要有基本的羈絆(防小號)。

### 3.6 SSR「和你」

場景只用公開頻道裡的事(聊過的話題、一起玩過的遊戲),不用私訊,也不用她對你的記憶內容;卡上不出現你的臉。一定現場生,排最高優先,但她唱歌時仍然等。

### 3.7 ComfyUI 和顯卡

- 生圖經 ComfyUI 的 API,也就是現有的 `packages/imagegen`(落地保存的工作佇列、唱歌時讓出顯卡、可以掛自訂 workflow)。**不另外接別家的服務**。
- ComfyUI 是 hostd 管的一個服務,提供 `imagegen` 這個能力,顯卡策略是 `on_demand`。它跑在哪一台是部署的事:原企劃估 Krea 2 Turbo fp8 要 16 GB 起,這張卡是 12 GB,所以十二月選模型時要一起決定「在這台用量化的模型」還是「在另一台電腦跑 ComfyUI」。兩種對 Core 來說是同一個 API。
- 主題只記 workflow 的代號,不記模型。換模型的工作是:新的 workflow 檔、重新校準相似度門檻、每個主題重審一組樣本。底片庫裡舊模型的圖可以發完為止。
- 她的 LoRA:owner 要找網路上那一份並確認授權。原企劃的提醒還在:作者不允許的話,整個企劃要改成委託繪師。

### 3.8 接進 V5

- 表和邏輯在 `cards` 外掛(主題、底片、卡、保底、圖鑑、檢舉)。
- 圖放產物庫(v5-architecture §11.2):底片是私有的,發卡時變成本人可見;進全服相簿才變成有連結就能看。
- 抽到、覺醒、被檢舉都是事件,進她的收件匣。
- 面板:主題(樣本、核可、上下架)、庫存和淘汰率、每日抽查、檢舉、機率表(改動留紀錄)。公開頁有機率表。

## 4. 回收

### 4.1 原則

1. **去處要有下文**:花了錢,自己看得到、她記得、或別人看得到。
2. **會重複發生**:每天或每週都有理由花,不是買一次就沒了。
3. **規模跟著餘額走**:錢多的人自然花得多(拍賣、買賣股票、手續費按比例)。
4. **花錢買不到羈絆**,也不拿感情催人花錢。這兩條是現有的規則。
5. **每週看數字**:目標是回收量至少是發放量的八成。面板已經有經濟健康表。

### 4.4 深海交易所

完整設計在 [exchange.md](exchange.md)。重點:

- **八家假公司**,代號像股票:DPSK(DipSick AI,她的老家)、CLSD(ClosedAI)、GOGL(Goggle)、NVDY(Envydia)、RICE(白飯食品)、WHLE(鯨落唱片)、CUBE(方塊礦業)、NAPS(打盹床業)。owner 2026-11-14:名單照這樣。
- 價格由程式模擬,一天 12 盤,單日漲跌幅 ±10%。新聞的種類和大小由程式抽,她只寫字。幾家公司會被真的事推一點(她的模型 API 塞車時 DPSK 會跌),一天最多 ±3%。
- **事件照真的股市**:週財報、除息、股東會紀念品、併購傳聞、現金增資、升降息、黑天鵝、熔斷、注意股 → 處置股 → 下市、新股抽籤。owner 2026-11-14:下市要開。
- **不印錢**:買股票的錢進金庫,賣的錢從金庫出,所有玩家合起來拿不走比放進去更多的錢。價格跑在資金前面時,大盤會被往下拉。
- **回收**:買賣各 1.5% 手續費,賣出再收 3% 交易稅,全部燒掉。
- 她是財經主播:每天行情圖、每週預估和財報講評;她看不到隱藏的數字,也不下場。
- **交易量表**(取代贊助榜):這一週誰買賣的金額最多。排的是交易量,不是賺賠,也不是身家。
- 上線前先離線模擬,再做兩週不能下單的紙上交易。

### 4.5 拍賣、優先券、樂透

- **每週拍賣**(owner 同意):一週一件,在一個討論串裡公開出價 24 小時,最後 5 分鐘有人出價就延長。得標的錢燒掉,沒得標的全數退回。拍的東西(例):這一週她怎麼叫你(她可以拒絕不雅的)、直播結尾感謝名單的第一位、替水族箱的一條魚取名、一個只此一件的卡框、提名一家新公司上市。
- **點歌優先券**(owner:不要競標,單純的優先券):固定價(草案 40)。用了之後你點的歌排到沒用券的人前面,同樣用券的照先後。一人一天最多兩張。取代現在沒人用的點歌券和獻詞。
- **每週樂透**(owner 同意):一張 10 魚幣,每人每週最多 20 張。獎金是售出金額的七成,三成燒掉。她每週抽一個人。

### 4.6 水族箱

取代房間集資(零筆)。直播畫面和網頁上有一個共用的水族箱:

- 買一條魚或一個擺設(草案 50 到 300),上面掛你的名字。
- 魚每週要飼料(草案 10);沒人餵就「游回深海」。這是持續的回收。
- 她看得到水族箱,會聊誰的魚。它也接上她是鯨魚娘的設定。
- 伺服器一起養到某個數量,解鎖一個新的佈景(取代沒人用的伺服器目標)。

**魚怎麼呈現**(owner 要先看到再決定):

- 魚是程式畫的,不用生圖:十種左右的輪廓 × 配色 × 花紋 × 大小,由購買時的種子決定,每條都不一樣。生圖開放後可以加少數「特別的魚」。
- 直播畫面:底部一條水帶(overlay 已經有畫布),魚游過時偶爾浮出主人的名字。
- 網頁:一整頁的水族箱,滑到魚上顯示名字、哪天買的、被餵了幾次。
- 她的鯨魚剪影偶爾游過;她心情低的時候水色暗一點。
- 動工之前先做一張靜態的示意圖給 owner 看。

工比較大(overlay 和網頁各一個元件),排在交易所之後。

## 6. V5 另外提的三項

這三項不在 owner 的企劃裡,是 V5 加的。owner 2026-11-14:三項都要。

### 6.1 里程碑卡

- **是什麼**:羈絆升到新的分級時(例如朋友 → 好朋友),她給你一張綁定的卡。不能買、不能抽、不能送。
- **卡上有什麼**:當下算的立繪(表情對應新的分級)、日期、她從一段共同記憶寫的一個場面。高分級本來就要一段共同記憶當門檻(v5-architecture §8.3),卡上寫的就是那一段。
- **為什麼要**:升級現在是無聲的,數字變了沒人知道。有了它,升級是一個看得見的時刻;圖鑑裡會多一排「你和她的經過」。
- **隱私**:場面只用你本來就看得到的內容(你們之間的對話),卡預設只有本人看得到。
- **工**:小。用的是每日卡的算圖和卡面。

### 6.2 頻道裡的掉落

- **是什麼**:頻道熱鬧的時候(草案:十分鐘內三個人以上、共二十則以上),她偶爾丟出一張卡,第一個按按鈕的人拿到。
- **不取代付費的每日卡**:掉落的卡帶一個只有掉落才有的限定部件。每人一天最多拿一張,每個頻道一天最多兩三次,要在那個頻道的設定裡打開。
- **為什麼要**:給「人在現場」一個理由,也是幾個人一起的事(誰搶到了會被講)。
- **風險**:會變成搶按鈕;有人用程式自動按。對策是隨機延遲出現、同一個人連續搶到會被跳過。它也是一個不收錢的卡片來源,所以要有上限。
- **工**:小到中。

### 6.3 願望單

- **是什麼**:你標記最多三個想要的部件(生圖卡開放後也可以標主題)。抽到時她會講(「你要的單片眼鏡」)。
- **不改機率**。機率表對每個人都一樣。想指定的話,生圖卡有鱗片可以換指定主題。
- **為什麼要**:她因此知道你喜歡什麼,會記得;抽到時多一句屬於你的話。
- **可以加的變化**(不建議):花魚幣「許願」讓接下來幾張的機率提高。它是一個回收口,但會讓機率表變複雜。
- **工**:很小。

## 9. 圖片式的訊息

她在 Discord 發的行情、圖表、個人卡是算出來的圖,不是一大段文字。

- **風格和網站一致**:同一張背景圖,上面是毛玻璃的面板,兩個強調色,字體和網站相同。設計 token 和 `packages/ui` 共用。
- **做法**:現有的分享預覽圖已經是 SVG → resvg → sharp(`packages/api/src/og.ts`)。照這條路做一個共用的 `render`:模板吃資料、吐 PNG。毛玻璃在 SVG 裡是「把背景的那一塊做高斯模糊,再蓋一層半透明和一條細邊」,不需要瀏覽器。要用到瀏覽器的只有 Live2D 立繪(cards.md §6)。
- 圖進產物庫(v5-architecture §11.2),當附件送出。資料沒變就用快取。
- **先做的幾張**:行情總覽、單一股票走勢、交易量表、個人卡(`/me`:羈絆的環加八個細項)、錢包(這一週的收支)、每週回顧、拍賣現況。
- 每張圖附一行文字摘要(Discord 的替代文字),重要的數字在文字裡也有。
- **背景圖**:owner 2026-11-14 決定暫時沿用現在公開頁那一張。它是遊戲美術,圖片訊息會被轉貼,所以背景做成一個設定,之後換成自己的圖或程式畫的背景(cards.md §5 的做法)時不用改模板。
